# Talkable vs Buildable

Some questions resolve by talking. Others need something to react to.

## 1. Talkable

- Goals, constraints, audiences, trade-offs, priorities, definitions of done.
- Keep these in the interview. Push until each has a committable answer.

## 2. Buildable

- Feel, layout density, interaction shape, information hierarchy, multi-step flows.
- Examples: one long form or three pages, how a transition should feel, which density reads better.
- When one appears, stop grilling that branch. Build the smallest throwaway that shows it, look at it, then answer in one line.

## 3. Rules

- Never talk through a buildable question for multiple rounds. Rephrasing without evidence inflates scope.
- Keep throwaways disposable: no tests, no polish, no reuse claims. Delete or rewrite after the decision.
- Return to the interview after reacting. Record the decision as if it had been answered verbally.
