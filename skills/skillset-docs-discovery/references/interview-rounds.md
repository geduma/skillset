# Interview Rounds

Ask in rounds where each round is the whole frontier: every question whose prerequisites are already settled.

## 1. Build the frontier

- Map open branches: goal, audience, constraints, scope boundaries, success criteria.
- Ask only questions with no unanswered prerequisites. Never ask what hinges on an answer not yet heard.
- Batch the frontier per round. Prefer a few dense rounds over a long drip of single questions.

## 2. Demand ownership

- The user steers scope. Invite correction on framing, fidelity, and drift every round.
- Passive agreement is the failure mode: long sessions with no pushback produce certainty without decisions.
- Treat "I don't know" as a real answer. Do not force guesses; route it to evidence or a throwaway.

## 3. Build on answers

- Later rounds must visibly reference earlier answers. If a question ignores prior context, reframe it.
- Surface implicit decisions: restate what the user assumed without stating, then ask for confirmation.
- End a branch when the answer is committable: specific enough to specify, build, or record.

## 4. Ask only what you cannot infer

- Infer from repo, docs, or conversation when possible. Ask only for what varies per user or per run.
- If a fact is missing and checkable, check it or ask for it once, then move on.
