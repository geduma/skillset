# Headings and Search Intent

One H1 per page. Headings serve users, search engines, and screen readers at the same time.

## 1. Structural rules

- Exactly one H1 per URL. It states the page promise and includes the primary topic once.
- H2 sections partition the H1 argument. H3 partitions one H2. Never skip levels for styling; use CSS for visual size.
- Multiple H2s are expected. Single-H2 or H2-free long pages are flat and hard to scan.
- Keep heading text concise: H1 under 70 characters, H2 as questions or tasks where possible.
- Headings must read as an outline. If the outline alone confuses, the page confuses.

## 2. Intent matching

Label every page before rewriting:

- Informational: `how`, `what`, `guide`. Answer with steps, definitions, examples.
- Navigational: brand or login queries. Answer with the direct destination.
- Commercial: `best`, `compare`, `review`. Answer with criteria, tables, pros and cons.
- Transactional: `buy`, `price`, `hire`. Answer with offer, proof, and CTA.

Reorder sections so the dominant intent is answered first. Secondary intents go lower. Do not mix two dominant intents on one URL; split the page.

## 3. Headings that win snippets

- Map each H2 to one question the SERP asks. Use People Also Ask and GSC queries as source.
- Example structure:
  - H2: `How to write meta titles that survive truncation`
    - H3: `Length and front-loading`
    - H3: `B2B versus ecommerce examples`
  - H2: `How to avoid duplicate titles at scale`
- Put a 40-60 word direct answer immediately under each H2 before elaborating. This block is what gets quoted.
- Use LSI and long-tail variants in H2/H3, not verbatim repetition of the title keyword.

## 4. What to reject

- H1 identical to meta title word for word.
- Multiple H1s from theme builders or logo markup.
- H2s used as styling for callouts or buttons.
- Keyword-stuffed heading chains with no question answered.
